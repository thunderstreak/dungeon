# 鼠标左键点击移动设计

## 目标

将当前角色移动方式从方向键 / WASD 控制，统一改为鼠标左键点击移动。

## 当前实现结论

- `src/entities/Player.ts` 同时存在两套输入链路：
  - `handleInput()`：方向键 / WASD 驱动网格移动
  - `handleClickMove()`：基于 `moveToScreen()` 的点击目标移动
- `src/scenes/TownScene.ts` 已在左键点击时调用 `player.moveToScreen(...)`
- `src/scenes/DungeonScene.ts` 已在左键点击地面时调用 `player.moveToScreen(...)`，点击怪物时优先用于目标选择

这说明点击移动能力已经存在，但当前仍与键盘移动并存，输入模型未彻底收口。

## 确认后的交互规则

1. 角色移动只由鼠标左键触发
2. 方向键与 WASD 完全失效，不再参与角色移动
3. 左键点击地面时，角色朝点击目标持续移动
4. 角色移动途中再次左键点击新的地面位置时，立即改道到新目标
5. 地牢场景中，点击怪物时优先走目标选择 / 攻击逻辑，不应触发地面移动
6. 城镇或 UI 面板阻塞状态下，维持现有“不可移动”的限制
7. NPC 对话、死亡等已有停止移动逻辑继续保留

## 推荐方案

采用“实体层收口”的方式：直接从 `Player` 中移除键盘输入初始化与 `handleInput()` 调用，仅保留点击移动链路。

原因：

- 输入职责最清晰，`Player` 不再维护两套互相竞争的输入源
- 现有场景层已经具备点击事件分流能力，改动范围小
- 能避免键盘输入在未来继续打断点击目标、造成隐性行为冲突

## 影响范围

### 1. 玩家实体

文件：`src/entities/Player.ts`

- 移除 `cursors` / `wasd` 字段
- 移除键盘输入初始化逻辑
- 移除或停用 `handleInput()`
- `update()` 仅保留点击移动、自动攻击、动画、血量同步等流程
- 保持 `moveToScreen()` 可重复调用，以支持移动途中立即改道

### 2. 城镇场景

文件：`src/scenes/TownScene.ts`

- 保持现有左键点击移动逻辑
- 继续在 UI 面板打开时阻止点击移动
- 继续通过摄像机滚动偏移把屏幕坐标换算为世界目标坐标

### 3. 地牢场景

文件：`src/scenes/DungeonScene.ts`

- 保持现有“点击怪物优先，不点怪才移动”的行为
- 确认点击地面时传入的目标坐标与当前摄像机跟随模式兼容
- 不改变自动攻击、怪物悬停高亮与目标锁定逻辑

## 风险与注意点

### 方向动画来源

`Player` 的移动动画仍依赖 `facingDirection`。移除键盘输入后，需要确认点击移动过程中的朝向仍会被正确更新，否则动画可能只保持旧朝向。

### 摄像机坐标系一致性

城镇场景手动滚动摄像机，地牢场景使用 `startFollow()`。两者传给 `moveToScreen()` 的坐标方式不同，实现时需要确保点击目标换算规则不被破坏。

### 点击怪物与点击地面冲突

地牢里必须维持“点怪不走、点地才走”的优先级，避免玩家试图选怪时角色误移动。

## 验收标准

1. 进入城镇后，方向键 / WASD 不再让玩家移动
2. 进入地牢后，方向键 / WASD 不再让玩家移动
3. 左键点击地面后，玩家会按当前点击移动逻辑前进
4. 移动过程中再次左键点击新的地面位置，玩家立即改道
5. 地牢点击怪物只会选中 / 攻击怪物，不会触发地面移动
6. UI 面板打开时，城镇中的点击移动仍被阻止
